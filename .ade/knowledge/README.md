# Project knowledge

What each role has learned about *this* project — the things that are true here
and nowhere else, and that would otherwise be rediscovered every session.

One file per role, named for the role: `qa.md`, `developer.md`, `architect.md`.
A role creates its own file the first time it has something worth keeping, and
appends a dated line after that. Newest last.

## What belongs here

Durable, role-specific, and useful to the same role next time:

- `qa.md` — the integration tests are flaky under parallel runs; serialize them
  before trusting a red.
- `developer.md` — the client in `src/api/` is generated by `npm run codegen`;
  editing it by hand is always wrong.
- `devops.md` — the staging deploy needs the migration run first, or it boots
  against a schema it cannot read.

Keep entries short and factual. Delete one when it stops being true: a stale
note is worse than no note, because it is believed.

## What does not belong here

**Anything another role has to agree with.** Interfaces, types, API contracts,
config keys and cross-cutting decisions go in `.ade/context/`; significant and
lasting decisions go in `.ade/context/decisions/` as ADRs.

The difference is who it binds. Knowledge is descriptive and yours — it helps
you work faster, and nobody is wrong for not having read it. A contract is
normative and shared — an agent that has not read it will contradict you.
Recording a contract here instead of in the context store is how parallel work
goes wrong, because the agent building alongside you never reads this file.

Secrets, credentials and tokens never go here. This directory is committed.

## Why it is committed

The knowledge is the project's, not the machine's. It travels with the repo, so
a teammate — or you on another machine — starts from what has already been
learned instead of rediscovering it.

Nothing here is ever copied back into `ade-setup`. That repository holds who the
agents are, which is shared by every project; this holds what is true about one
project, which is shared by none.
