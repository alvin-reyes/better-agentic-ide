# 0020: The isolation test runs in phases, scans two tiers in every encoding, and reports one verdict in a fixed order

- **Status:** Accepted (2026-11-08). Approved by the owner on 2026-11-08 with the F1 plan; accepted on 2026-11-08, when the delta review of revisions 5 to 5g of the F1 design passed. Approved with O5, O8 and the stated limits. With the F1 design (section 15) and the verification gate in `docs/architecture.md`, approved in substance with the plan (O5) and in its wording when that review passed (2026-11-08).
- **Revisions:** 2026-11-08 first version; revised the same day after the adversarial review (B1, B3, B4, M3, M4, M5, M13, minors 7 and 8); revision 3 after the re-review (NB2, M-b, M-d, minors 1, 3, 4 and 10); revision 4 (B2, minors 4 and 5); revision 5 (M-B, M-D, minors 1 and 2).
- **Context:**
  - PE-4 AC9 states what the test proves, and F1.12 hands its mechanics to the architect:
    - roots in two tiers (N-B1);
    - OS stores and encodings (N-B2);
    - slice-0 stand-ins (N-M2);
    - a driver that never ships (N-M3);
    - RC-2's listing (N-M5).
  - Slice 0 must fail with exactly one verdict.
- **Decision:**
  - **Where it lives:** a Rust crate `src-tauri/isotest`. It drives a harness build (bundle id `com.betterterminal.isotest`, cargo feature `isotest-driver`, Vite define `VITE_ADE_ISOTEST`, the helper bundled as in release, and a home root compiled in as `ADE_ISOTEST_HOME`, which the rebuild uses in place of the real home, ADR 0016) through ADE's own commands and DOM. A pinned real Claude Code runs `claude mcp add` and `claude mcp list`, which need no account.
  - **Phases:** B, then a baseline with nothing running, then P1a (the default creates A, then is quiesced: one flush of its state and WebKit store, then its snapshot, sync and 20 s session timers and further store flushes stopped), P1b (A's start, both running; snapshot while both run), P1c (the default quits, A idle), P2 (A alone), then P3 (the default's steps, from slice 4; slice 6's reopen and quit checked like P1b and P1c).
  - **Attribution:** only the default running, the marker rule (no marker of A but A's registry entry); only A running, A's rule (A's allowed locations or exempt); whenever both run (P1b, A's start with the default quiesced; P1c, the default's quit; slice 6's reopen and the quit after it), by location: a change in a default-owned location (its `ProfilePaths` locations, the registry files, its own channel and lock files, and its persistent webview store's per-bundle folders; in slice 0 a stand-in table of the same rows for today's code, which slice 1's table must cover) gets the marker rule, whichever process made it; everything else A's rule (A's allowed locations or exempt). This includes the browser engine's writes for the shared bundle id during P1b (revision 5, M-B): in the default's per-bundle webview, cache and HTTP-storage folders, the marker rule; elsewhere (the per-user cache's Metal folders, the per-user temp's `<id>/WebKit/`, WebView2 and WebKitGTK folders outside the default's), A's rule, so exempt or a finding. The default's late flushes and quit writes are therefore never counted as A's by timing.
  - **The leak detector's real-Claude test** (ADR 0023) runs in the same workflow on macOS and Windows and counts toward the job's result: a failure, skip or timeout is red (revision 5, M-D).
  - **The nested Claude Code step** (ADR 0023) asserts that the nested level's MCP log folder exists under A's split home; a failed assert is "step could not run".
  - **Tier 1** (the compiled harness home; on Windows also `APPDATA` and `LOCALAPPDATA` for every process ADE starts, which move what reads the variables but not Known-Folder readers, so those land in tier 2) is fully rule-checked.
  - **Links are never followed:** walks use `lstat`, a link is recorded as a link (on Windows every reparse point, junctions included), deletes remove the link (the harness home holds `Library/Keychains` linked to the runner's real one). Paths are absolute, so Windows long paths work, and are compared case-insensitively on Windows (revision 5, minors 1 and 2, M-D).
  - **Tier 2** (real per-user and system roots: `HKCU`, the real `%USERPROFILE%`, `%APPDATA%` and `%LOCALAPPDATA%` trees, macOS per-bundle files and `sharedfilelist`, the per-user temp and cache folders) is rule-checked on paths with an app-named component, and its changed files are searched in full for markers.
  - `~/Library/Saved Application State/<id>.savedState` must be absent: an encrypted store is never exempt.
  - **Markers** are searched case-folded, as raw bytes, JSON `\u` escapes, UTF-16LE and BE, base64 and base64url, and ROT13. Snappy blocks, gzip, zlib and brotli are decompressed; SQLite files are read raw and through cell decoding (WAL and SHM included); plists and OLE compound files are parsed. File and key names are searched too.
  - **Exemptions** in `exemptions.toml` are exact files, per-segment patterns (`<id>`, `<hex>`, `<n>`, `*` within one segment, never `**`; each pattern holds `<id>` or an app-specific literal, and `*` is never the first segment after the root) or `HKCU` value patterns, each with a reason; the grammar and every exemption after slice 0 need the owner's approval.
  - **One verdict:** the first failing check in this order: step could not run; scanner blind; marker outside A; write outside A; B changed; marker not in A; else pass.
  - Determinism: two runs on two fresh runners per platform must give the same verdict and the same marker-finding keys (marker, kind, location class, normalised store root; never offset, file within a store or encoding, which compaction and checkpoints move); kind-4 findings are reported, not compared. Every kind-4 finding is printed in the job summary, and slice 0 is Done only after they are reviewed.
  - **Slice 0's mark** is `isotest/EXPECTED` (`xfail: marker of A found outside A's allowed locations`), replaced by `expect: pass` in slice 1, whose story also adds the CI refusal of any `xfail` line, so slice 0's own runs are not refused. Slice 0 has no folder-picker step (it arrives with ADR 0021's picker).
  - `isotest-list` gives RC-2 the same roots and diff.
  - A release check fails on a `#[used]` sentinel compiled only under `isotest-driver`, on the harness bundle id `com.betterterminal.isotest`, and on `__adeDriver` in the frontend bundle (`env!` embeds the home's value, not its name).
- **Consequences:**
  - A tier-2 write by ADE carrying no marker, to a path not named after the app, is not caught. This is the accepted limit, alongside the PRD's "created and removed before the check".
  - While both run (P1b, A starting; P1c, A idle and the default quitting), an unmarked write by A into a default-owned location is attributed to the default and passes. Bounded: for ADE's own paths, A's code cannot name them (`ProfilePaths`, the static test); for the per-bundle webview, cache and HTTP-storage folders, which A shares with the default by bundle id, only by E7.2's measurement that a non-persistent store does not write them, repeated by slice 0's probe on each platform; repeated writes recur in P2 under A's rule. Approved by the owner with the plan, 2026-11-08.
  - OS-wide search indexes are not scanned.
  - Encrypted stores cannot be searched; they must be absent or hold only what PE-7 puts in the OS secret store.
  - CI needs two runners per platform for the isolation job.
  - The CI keychain, Secret Service and Xvfb set-up is DevOps's (`docs/ops.md`).
