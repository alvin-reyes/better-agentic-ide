# 0040: Sync splits a key into a public part and a local part, and the import joins them back

- Status: Proposed (2026-11-15), with the F4 design revision 3; not approved. Rewritten in revision 2 after the blocked review of revision 1 (findings B1, B2, B3) and the owner's decision of 2026-11-15; revised in revision 3 after the delta review of revision 2 (finding N-B3: each rule's scope, per row) and the owner's answers of 2026-11-15 to F4 OQ-14 to OQ-21. The number is provisional (see the README's numbering notes).
- Context:
  - The owner approved F4 OQ-5 on 2026-11-10: workspace and checkout paths are stripped from ADE sync's export in the keys F4 WS-7 AC3 lists, while this machine keeps them. F2 OB-10 AC2 and OB-14 AC5 need the same for hub tabs. The PRD asks for one design for both.
  - Today `import_state` replaces a shared key's whole local value when the repo copy is newer and puts back only secret fields (`sync.rs:285`, `:99`). A plain strip at export would lose this machine's paths as soon as another machine exports the key.
  - Revision 1 stripped an orchestrator `projectDir` or an agent-tracker `cwd` only inside a workspace folder "known to this profile", which needed discovery at export and lost other machines' paths. **The owner decided on 2026-11-15: strip all paths.** A `projectDir` and a `cwd` are never synced, for anyone, hub or not; each machine keeps its own.
  - PRD revisions 3.4 to 3.7 (pending the owner's approval of their text) add rules for those two fields only: the import never takes another machine's value; a value that cannot be read as the key's list of entries is neither exported nor imported; the repository's current files are cleaned (OQ-14); the skip is shown (OQ-15). PRD 3.6 F4.9: "Every rule they add … concerns only those two fields in those two keys, and none of F2's rows". Revision 2 of this ADR applied the never-take rule and the cleanup to every key; the delta review (N-B3) found that contradicts the PRD.
  - The owner answered OQ-14 to OQ-21 on 2026-11-15, each as recommended: the cleanup (OQ-14) and the notice (OQ-15) are built.
  - Spec: `docs/superpowers/specs/2026-11-15-workspaces-design.md`, section 9. Contract: `.ade/context/sync-local-fields.md`.
- Decision:
  - **Local fields are fixed by the key and the field's name, or by a field of the same saved tab.** Sync looks at no workspace, no record, no discovery and no folder. One module, `sync_local.rs`: `public(key, value)` removes the local fields; `join(key, imported, local)` puts this machine's local fields back onto the imported entries; `clean(key, repo_value)` is the cleanup.
  - It is re-apply, not a three-way merge: the newer copy still wins whole, then this machine's local fields go back onto the entries that are still there. An entry deleted elsewhere stays deleted. Entries are matched by id: a session's `id`; a tracker entry's new `id`, else `paneId` and `startTime`; a tab set's `id` and `name` with the tab's index.
  - **Each rule's scope, per row:**
    - **`better-terminal-orchestrator` and `better-terminal-agent-tracker` (S0):** every `projectDir`, respectively every `cwd`, anywhere inside each element is local. The value must be a JSON array (elements that are not objects pass as they are); a local value that is not is not exported, and an imported copy that is not is not imported, both recorded as skipped. An imported value of the field is **never taken**. The repository's current file is cleaned of the field when it is a list (OQ-14), keeping its timestamp and device. A skipped key is kept in this machine's `sync-state.json` until it next syncs and is shown in Settings → Sync there (OQ-15).
    - **`better-terminal-workspaces`, tab sets (S1):** F2's `cwd` and `hub` of each tab entry are local. The import keeps this machine's values; where this machine holds none for an entry, the imported entry's value stands (the PRD's whole rule for this row). No unreadable rule beyond today's, no cleanup, no report.
    - **`ade-session` (S1; exported, never imported):** a saved tab with `workspace` or `hub` is exported as an allowlist of fields that hold no path (`hub: true` is one of them). Any field added later is left out until it is listed. Unreadable as today. No cleanup, no report.
  - **Invariants, tested per row:** `public(join(p, l)) == public(p)`; every local field this machine holds for an id in both is kept; `join(public(v), v) == v` when every entry holding a local field has a unique id; the join has exactly the imported entries; and, for the two S0 rows, no local value in a join comes from the imported copy.
  - Values are compared as parsed JSON, not as text.
- Consequences:
  - F2's hub-tab strip and F4's workspace strip are rows of one table, with one set of two-machine tests. F2's rows get exactly what the PRD gives them; F2's design may adopt the stricter S0 rules for its rows.
  - Sync reads no hub file, has no fail-closed state, does not depend on the workspace record, and adds no time to the launch import or the close.
  - **It changes what everyone syncs, hub or not**, and ships ahead of the workspace feature as slice S0 (OQ-19). An orchestrator session received from another machine has no project folder; Dispatch makes one here. An agent run received from another machine is not attributed to a project and is never joined to a pane here (OQ-20, design 9.8). Each machine's own sessions and runs keep their folders.
  - Paths synced before this change stay in the sync repo's git history (OQ-16); the current files of the two keys are cleaned at a machine's first sync on this build.
  - A machine on an older build writes its folders back when it exports, and loses its own `projectDir` and `cwd` values for the entries it imports. The guarantee holds once every machine syncing to the repo runs this build. The release note says so (OQ-17, devops).
  - Values a machine imported before this build cannot be told from its own and count as its own.
  - `ade-session` still exports, as today, the folder of a plain tab, an editor tab's file and a contracts tab's root: the PRD strips workspace and hub tabs only. The design asks the owner whether to remove those too.
  - Rejected: stripping only inside known workspace folders, with discovery at export (revision 1); marking entries when they are written (needs the same knowledge at write time and misses older entries); a three-way merge (needs a base copy per key that sync does not keep); taking an imported `projectDir` or `cwd` when this machine has none (the owner's rule is that each machine keeps its own); one never-take, unreadable and cleanup rule for every key (revision 2; the PRD scopes them to two fields).
