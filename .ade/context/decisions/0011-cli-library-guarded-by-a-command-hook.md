# 0011: The CLI library is guarded by a command hook ADE ships

- Status: Accepted (owner, 2026-10-30; refined 2026-11-01: `disableAllHooks: false` only with a guard), with the plan `_bmad-output/plan-cli-library-and-mcps.md` (approved after six adversarial review rounds; round 6 passed with minors at 5c34845). **Amends ADR 0003** (`0003-agent-status-hooks-helper-endpoint`).
- Context:
  - Agents use command-line tools as much as MCP servers. In ADE's Continuous mode, an agent can run `gh secret set`, `gh release delete`, `vercel --prod` or `stripe pay` without a prompt.
  - Claude Code's Bash permission rules are prefix patterns. The docs say a rule "isn't a security boundary around the program": rules miss runners, aliases, global flags, `sh -c`, absolute paths and npm scripts.
  - `.claude/settings.json` (and its hooks) loads only from the session's working directory. Skills and the root `.claude/settings.local.json` load from parent folders and from the main checkout in worktrees.
  - ADR 0003 said "ADE never returns hook decisions".
- Decision:
  - **A PreToolUse guard ships in ADE's helper:** `ade-hook guard`, installed beside ADE, outside every project.
    - It is run by absolute path in shell form (`GUARD_CMD`), which every Claude Code version honours. A missing helper asks, naming the fix (denies when headless).
    - It classifies each library CLI against a table built from a recorded vendor fixture (P6(b)), re-captured quarterly (P6(c)).
    - It never returns `allow` and never rewrites a command. It asks on risky and unknown leaves, computed names and computed evaluator code. It denies when headless (`--headless`, or `CLAUDE_CODE_ENTRYPOINT` `sdk-*`). It fails closed on parse failures, oversize input, panics, and (on Claude Code ≥ 2.1.295) crashes and timeouts.
    - Text read from disk triggers fail-closed rules only when it names a guarded CLI.
  - **Where the guard and rules go:**
    - On every ADE launch, in the one shared `--settings` value, with Orgo's ask rules. This is the amendment to Orgo's AC11.
      - **`disableAllHooks: false` is set only on launches that carry the guard** (owner ruling, 2026-11-01). Before the guard exists, or without the helper, the value is just `{"permissions": {"ask": …}}`.
      - `launch_rules()` returns both guard variants, `{ interactive, headless }`, and `buildLaunchCommand` picks one from `opts.headless`.
    - In the main checkout's root `.claude/settings.local.json`, for sessions the user starts in the repository.
    - Ask and Read rules sit on top. ADE never writes a tracked file.
  - **Threat model.** The guard defends against an agent's honest or careless commands and the indirections agents really write: scripts by path, `bash -c`, eval of built strings, `xargs`, write-then-run, runners and npm scripts.
    - It does **not** defend against deliberate obfuscation. That is left to Claude Code's own ask and deny rules, the user's review, the CLI's own credential scope, and the Bash sandbox if the user enables it.
    - It always fails toward asking.
    - Reviews judge the guard against this model.
  - **Other rules:**
    - Skills are rendered in Rust from the CLI id, with frontmatter of `name` and `description` only.
    - Installs are typed into a new tab at the project root and never run.
    - ADE never executes project code; versions and sign-in checks run on click.
  - **In Continuous mode the guard's `ask` counts toward P2 only after manual check V1** (ADR 0012, `0012-ade-is-an-ide-plus-a-harness-principles-p1-p6`). On a version where V1 fails, the guard denies under `bypassPermissions`. Manual checks follow ADR 0009 (`0009-manual-checks-do-not-gate-done`, unmerged on `docs/claude-md-paths`).
- Consequences:
  - Each new CLI is a fixture, a guard table, rules, corpora and a line in the quarterly re-capture. v1 builds gh; stripe, vercel and wrangler wait for a named need.
  - The guard is a parser that must keep up with shell forms and CLI releases. Unknown leaves and computed names ask, so falling behind adds prompts rather than removing them. The estimated false-ask rate is 0.3–0.7% of Bash calls, to be measured (V8).
  - `disableAllHooks: false` on a guarded launch also re-enables the user's and project's other hooks for that session where a settings file had turned them off. The tab says so. Unguarded launches don't pay this cost.
  - Not covered: Windows, Claude Code sessions outside the repository, other agents, and `allowManagedHooksOnly`, `--safe-mode` or managed `disableAllHooks`.
- Numbering: final at the merge of `feat/cli-guard` (2026-11-09); 0010 is Orgo's. ADR `0009-manual-checks-do-not-gate-done`, cited above, is unmerged on `docs/claude-md-paths` and needs a new number (0009 on main is the side panel); see the decision log's numbering notes.
- Amendment (2026-11-09, sub-terminals story 9, from the open-terminals spec's "The guard and `ade open`"):
  - `"$ADE_HOOK_BIN"`, `$ADE_HOOK_BIN` and `${ADE_HOOK_BIN}` resolve to ADE's helper (the session's absolute value, else `ade-hook`), unless the line assigns `ADE_HOOK_BIN`; then the line's own rules apply, and an unresolved name still asks.
  - For the helper (`ade-hook` or `ade`) with a verb in `tables::ADE_VERBS` (`open` only), the words after `--` are classified as the command, as a runner's are. Without `--`, and for any other verb (`help`, `guard`, the hook), nothing is classified and nothing asks.
  - The command is classified in the folder the new shell starts in: `--cwd` joined to the line's current folder and normalised lexically (as `ade_cli::normalise` does), else the line's current folder. `open`'s flags are read as the CLI reads them, so a flag's value (`--name --`) is never the separator. A computed `--cwd` is a folder the guard can't name: any read relative to it (a script, a sourced file, a `package.json`), `..` included, asks. A computed word among `open`'s flags asks. The line's own folder is unchanged after the `ade open` (review finding B1, 2026-11-09).
  - The guard's tests enumerate `ADE_VERBS` and fail on a verb without a test row. `guard` and hook mode are unchanged.
- Amendment 4 (2026-11-09, owner's decision after four rounds of form-by-form fixes in story 9): variable resolution fails closed.
  - Context: the pre-pass recognised assignments only behind literal command names, so `builtin printf -v IFS /`, `p=printf; $p -v IFS /`, `trap IFS=/ DEBUG`, zsh's `$=X` and `$X:t` and others let a known value split into `open -- gh …`. Each round's list of forms missed the next form.
  - Decision: one general rule instead of a list of forms. An external command can't assign the shell's variables, so the pre-pass only has to name each command with certainty. A command it can't name (computed, glob, a wrapper with a computed target) disqualifies the line: no variable resolves after that, positional parameters unbind and IFS is open. A named builtin either has its assignments recorded (the names become unknown) or is on the disqualifying list. The finite set of bash and zsh builtins is what the rule enumerates, not shell forms. zsh's splitting expansions (`$=X`, `${=X}`, `~`, `^`) are may-split and modifiers (`$X:t`) are computed. The details are in `.ade/context/cli-guard.md`, "Variable resolution fails closed".
  - Consequences: more lines ask, those that combine one of these builtins or a computed command with a value the guard has to know (for example `trap … EXIT; X=echo; $X hi`). Everyday lines (`git status`, `npm test`, `X=1; echo $X`, `set -euo pipefail; …`) are unchanged. Aliases and functions from the user's shell setup stay outside the guard, as before.
- Amendment 5 (2026-11-10, the owner's two decisions of 2026-11-09 in story 9; supersedes amendment 4's resolution rule): the guard never resolves a variable, and a line that remaps a command name or runs code built from data asks.
  - Context: amendment 4 kept resolving variables under strict conditions. Its re-check still found forms that set a value or IFS where the pre-pass didn't look (`_=echo; : gh; $_ …`, zsh's `argv`, `$[IFS=1]`, `{IFS}>…`, `${(P)N::=…}`, `mapfile -C`, `{printf,-v,IFS,/}`), and older gaps where a name is remapped (`functions[ls]=…`, `hash -p`, aliases) or code is built from data (`${(e)Y}`, `${Y@P}`, arithmetic on `Y='x[$(…)]'`).
  - Decision 1, no resolution: every expansion (`$VAR`, `${…}`, `$_`, `$1`, `$@`, …) is unknown. An unknown word asks in a command-name position, as `ade open`'s verb, `--name`, `--split` or `--cwd` value (or any word among its flags), as a word after `--` the guard judges, and as an argument a guarded CLI's rules read. Given to an unguarded command it asks nothing (`X=1; echo $X`). The one exception: `"$ADE_HOOK_BIN"`, `$ADE_HOOK_BIN` or `${ADE_HOOK_BIN}` as the command word is the helper from the session, only when the session's value is an absolute path (unset, an unquoted one vanishes and the next word runs; a relative one is looked up on PATH: amendment 1's `ade-hook` fallback is withdrawn), and unless anything on the line can assign `ADE_HOOK_BIN` (in any form, a wrapper's `env`/`sudo` `NAME=VALUE` included) or disqualifies. `~` and a bare `cd` follow the same rule for `HOME`. The resolution machinery (`Ev`, `resolve`, `settle`, `positional`, `external_path`, `path_basename`, `push_value`, `modifier_next`, `SPECIAL`, `SAFE_SET_OPTIONS`, bound `$1`…) is deleted.
  - Decision 2, remapping and code from data ask: `alias`, `unalias`, `shopt expand_aliases`, `hash -p`/`hash NAME=PATH`, `autoload`, `enable`/`disable`, zsh's `functions` and assignments to `functions`/`aliases`/`galiases`/`saliases`/`commands`/`builtins`/`dis_*`/`functions_source`; zsh's `e` flag (and `%`, `P`), bash's `${…@P}`, glob qualifiers (`*(e:…:)`, `*(+f)`); arithmetic whose operands aren't all literal integers (`$((…))`, `$[…]`, `((…))`, `let`, subscripts, `[[ … -eq … ]]` and the other five, substring offsets); `printf -v`, `read`, `mapfile`, `unset` into a subscripted name. Functions defined on the line are not remaps: as before, the guard follows them at their call sites (or as if run when never called).
  - Found and closed while implementing, same two rules (each confirmed in real bash 5.3 or zsh 5.9 under `env -i`, with fake binaries): `env`/`env -S`/`sudo` `NAME=VALUE` for `ADE_HOOK_BIN`; `set -k`, `set -o keyword`, `shopt -o keyword`; `${!x}`; `[[ -v … ]]`, `test -v`, `[ -v … ]`; `${a[@]:off}`; an array's `[KEY]=` (and `declare A=(…)`, which used to fail to parse and was then quiet unless the line named a guarded CLI); zsh's `=(…)`; `BASH_ENV`, `PS0`, `PS1`, `PS2`, `PS4` (under `set -x`) and `PROMPT_COMMAND`; zsh's `${~x}`, `$~x`, `setopt globsubst`, `set -o globsubst`, `emulate sh`, `zsh -o globsubst`, and the `P` flag; a computed `trap` action; `~` after `HOME=…`; a sourced file the guard can't parse; an unquoted expansion in a gh `Special` leaf (it may split into `-X DELETE` or `--delete-branch`).
  - `for ((i=0;i<3;i++)); do …; done` stays quiet, soundly: the counter's initial value is a literal integer, the condition and step use only the counter and literal integers, and once every text is read (sourced files and function bodies included) the counter is assigned nowhere else and nothing disqualifies. Otherwise it asks.
  - zsh's `=cmd` asks: any unquoted word starting `=` and a name character, in any position, since zsh expands it everywhere and a wrapper (`sudo`, `xargs`, `env`) makes an argument a command name. `echo =x` asks too.
  - Out of scope (the only accepted exclusions): aliases, functions and options set in the user's rc files.
  - Consequences: more lines ask. Now asks by design: `X=gh; $X pr view` and `S=/usr/local/bin; $S/gh pr view`; also `"$D/x"`, `. "$HOME/.cargo/env"`, `cd "$D" && npm test`, `f() { gh "$@"; }; f repo view`, `"$ADE_HOOK_BIN" open --name "$X"` (or a computed `--cwd`), `[[ $n -gt 3 ]]`, `n=$((n+1))`, `declare -A A=([k]=v)`, `alias` with no arguments, `echo =x`, zsh's `${x:h}`. Unchanged and quiet: `git status`, `npm test`, `cargo test`, `ls -la`, `cd x && git log`, `X=1; echo $X`, `for f in *.ts; do echo "$f"; done`, `gh pr view 12`, `set -euo pipefail; …`, `exec 2>&1; …`, `echo $((2+3))`, `source ~/.cargo/env`. The rules are in `.ade/context/cli-guard.md`, "Expansions are never resolved" and "Constructs that ask".
  - Mutation check (2026-11-10, one condition per mutant, `cargo test --lib cli_guard`): 233 mutants over three passes. 51 survived the first pass; each got a row that isolates it (`amendment_5_mutation_pins`), or its condition was removed as equivalent (bash rejects the form, or another rule always fires first). Three equivalent mutants remain: `hook_bin`'s own `is_hook_bin` check (any other computed command word disqualifies the line in the pre-pass first), and the lexer's `word_end` tests for `word (…)` and `a= (…)` (bash rejects both as syntax errors, so nothing runs). Correction (amendment 6): "bash rejects both" is not true of zsh, where `ls (a|b)` is a valid glob group and `echo (a|b)(e:'…':)` runs code from data; the `word (…)` survivor is resolved in amendment 6. The first-pass survivors whose conditions were deleted, rather than pinned (m4 of the sixth re-check): `sublit_empty` (an empty subscript; a bash error), `for_ident` and `for_value_empty` (a `for ((…))` NAME that isn't an identifier, or no value; bash syntax errors), `for_select_disq` (`select` disqualified the line), `select_reply` (`select` assigned REPLY; this deletion was unsound, see amendment 6's B3), `gh_split_method` (a computed `--method` value as its own split check; `api()` judges a computed `-X`/`--method` itself). Rewritten into an equivalent form, not deleted: `int_word_inner` and `is_hook_inner` (now a `plain: true` pattern), `bang_alllit` (now `names_only`), `hook_abs` (now `hook_rel`: an unset or relative value is never the helper), `printf_v_computed` and `set_o_computed` (pinned by `printf -v "$N" x` and `set -o "$O"`).
- Amendment 6 (2026-11-10, the owner's decision of 2026-11-10 after story 9's sixth adversarial re-check): fix only the three holes story 9 introduced, ship v0.23.1, and defer the older gaps to a guard-hardening story.
  - Context: the re-check found (B3) that amendment 5's `for ((…))` rule missed names the shell sets by itself: `for ((_=0;_<3;_++)); do echo 'a[$(gh …)]' >/dev/null; done`, and the same with `BASH_REMATCH` after `[[ … =~ ]]` and `REPLY` after `select`, each run `gh` from data (confirmed in bash 5.3 under `env -i` with a fake `gh`); (B4) that `. x.sh`/`source x.sh` was read as `./x.sh`, while bash's `.`/`source` and zsh's `.` search PATH first (`PATH=$PWD/o:$PATH; . x.sh` ran `o/x.sh`); and (B1, the story-9 part) that a function on the line hid the command `ade open --` types (`gh() { :; }; "$ADE_HOOK_BIN" open -- gh repo delete o/r` was quiet, though the new terminal has no such function).
  - Decision: a `for ((…))` counter is quiet only when it is a plain counter (`resolve::plain_counter`: lowercase letters, digits and `_`; not `_`; not one of `resolve::SHELL_SET`, zsh's lowercase specials and module arrays such as `argv`, `status`, `pipestatus`, `path`, `cdpath`, `fpath`, `manpath`, `module_path`, `mailpath`, `psvar`, `watch`, `fignore`, `match`, `reply`), on top of amendment 5's conditions; `select` counts as assigning REPLY. A sourced name with no slash asks (`. ./x.sh`, `source ./x.sh`, `. ~/.cargo/env` are followed as before). The words after `open --` are never resolved to a function defined on the line (the scope's functions are set aside while they are judged and restored afterwards); a function's self-recursion through `open --` therefore can't hide anything (`f() { "$ADE_HOOK_BIN" open -- f; }; f` types `f`, which the new terminal doesn't have). m2: a `(` after a blank in a simple command that isn't `f ()`/`f ( )` is zsh's glob group and asks as a glob qualifier does (bash rejects it, so nothing changes there).
  - Mutation check (2026-11-10, one condition per mutant, `cargo test --lib cli_guard`, on a scratch copy): 88 mutants (14 conditions, one per `SHELL_SET` entry). All 14 condition mutants are killed, among them `select` assigning REPLY, restoring the scope's functions after `open --`, and amendment 5's `word (…)` survivor (killed by `f ( ) { …; }`). 15 `SHELL_SET` entries survived: zsh's remapping arrays (`functions`, `aliases`, `commands`, `builtins`, `functions_source`, `galiases`, `saliases`, `dis_*`), which the remap rule flags first. They were removed from the set; the test's own list of names still checks that each one asks.
  - Known gaps, deferred to the guard-hardening story (open in v0.23.1): B1 in general (functions named like guarded CLIs; `command`/`builtin`/wrappers past a function); B2 (disk text that runs its arguments); M1 (files changed earlier on the line); M2 (PATH, or a path-named gh); M3 (startup files: `ZDOTDIR`, `HOME`, `--rcfile`, `--init-file`, `ENV`); m1 (unlisted runners: `script`, `at`, `osascript`, `vim`, `awk`/`perl`/`python` code strings); m3 (the `~`/`HOME` exception, which needs the owner's sign-off). They are listed in `.ade/context/cli-guard.md`, "Known gaps".
  - Consequences: more lines ask: an uppercase or shell-set `for ((…))` counter (`for ((N=0;N<3;N++))`), `. x.sh` and `source x.sh`, `ade open -- gh …` after a line function named `gh`, and zsh's `ls (a|b)`. `for ((i=0;i<3;i++)); do echo hi; done` stays quiet.
