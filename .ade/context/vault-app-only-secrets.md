# Vault: app-only secrets

Status: approved with `_bmad-output/plan-anthropic-key-in-vault.md` (ADR 0013, accepted 2026-10-30). It becomes current as Stories A and B are Done.

- **App-only names** are listed as literals in `APP_ONLY` in `src-tauri/src/vault.rs`. Today the list is `ADE_ORCHESTRATOR_ANTHROPIC_KEY`, also exported to Rust as `vault::ORCHESTRATOR_ANTHROPIC_KEY`. `vault::in_terminals(name)` is the one test of the list. Each name must pass `valid_name` and must not start with `ANTHROPIC_` or `CLAUDE_`.
- **They are never in a terminal's environment.** `terminal_env` filters the map it returns, on both the cached path and the fresh-read path. The cache itself keeps every name, so its complete-read check still holds.
- **`vault_list`** returns `{ name, note, updatedAt, inTerminals }`. `inTerminals` is computed, not stored. `vault-index.json` is unchanged. TypeScript keeps no list of its own: the Secrets tab (`IntegrationsPanel.tsx`) marks `inTerminals: false` rows "Not in terminals", and picks the save notice from the `vault_list` entry it reads back after `vault_set` (a neutral "saved" notice, and no error, when that read-back fails).
- **`vault_get`** rejects with exactly `"not found"` when there is no entry. Other errors keep `keychain_error`'s text.
- **Readers of `ADE_ORCHESTRATOR_ANTHROPIC_KEY`** (from Story B): the Orchestrator's Anthropic provider (`src/lib/anthropic.ts`) and the one-time move (`src/lib/anthropicKey.ts`). Any `vault_get` allowlist must include it, alongside `DEEPSEEK_API_KEY`. `src/lib/__tests__/vaultGetCallers.test.ts` lists every caller. The Orchestrator has no fallback: not to an `ANTHROPIC_API_KEY` entry, not to the old setting. `"not found"` or `""` gives "No Anthropic API key set. Go to Settings → AI API to add one."; any other rejection is shown as the vault's own message.
- **`src/lib/anthropicKey.ts`** (from Story B) exports `ANTHROPIC_VAULT_NAME` (equal to the Rust literal), `LEGACY_FIELD`, `ANTHROPIC_KEY_NOTE` ("Orchestrator: Anthropic API key. Not exported to terminals."), `moveAnthropicKeyToVault(): Promise<"moved" | "stripped" | "nothing" | "failed">` (never throws), `lastMoveError()`, `lastMoveFailure(): { reason, keyInVault } | null` (`keyInVault` is true when only the settings write failed), `hasSavedCopy()` (localStorage holds a non-empty string field), `carryLegacyField(json)` and `removeSavedCopy()`. `removeSavedCopy` rejects with the raw error when the disk write fails (settings untouched), and with a `SavedCopyError` whose `settingsCleared` is true when only the snapshot scrub failed or skipped files. Its only static import is `@tauri-apps/api/core`; `removeSavedCopy` loads `./persistence` dynamically for `flushNow`.
- **The move's refinements** (Story B review fixes): a vault entry holding `""` is not "the vault wins" and is overwritten. When the read-back differs after step 3 found no usable entry (none, or `""`), the move makes a best-effort `vault_delete` of the name before failing, so the next launch doesn't take a wrong value as the vault's key. With nothing to move, the boot scrub runs only if `vault_list` (names only) holds `ADE_ORCHESTRATOR_ANTHROPIC_KEY`; otherwise, or if the list can't be read, it is skipped, so a restore that silently missed the settings key can't strip the only copies left. A `vault_list` call is names only and is not counted as a vault read in "no vault call".
- **The old setting field `anthropicApiKey`** (from Story B) is named only as `LEGACY_FIELD` in `src/lib/anthropicKey.ts`. The settings store never holds it (`migrate()` drops it); `persistSettings` passes its JSON through `carryLegacyField`, which copies the field from the current localStorage value only while it is there. It is also in `SECRET_FIELDS` in `src-tauri/src/sync.rs`, which strips it, and `state_scrub_secrets` uses that list (through `sync::strip_secrets`, now `pub(crate)`).
- **`state_scrub_secrets({ atBoot })`** (from Story B, `state::scrub_secrets(state_dir, at_boot) -> ScrubReport`): strips `SECRET_FIELDS` from `better-terminal-settings.json` and deletes `.better-terminal-settings.json.*.tmp` in every `snapshots/*/`, `.kv-old-*` and `.kv-restore-*` directory (stripped, never deleted), and in `kv/` only when `atBoot` is true. Writes only changed files, with `atomic_write`. Returns `ScrubReport { changed, skipped }` (JSON `{ "changed": n, "skipped": n }`): `skipped` counts files that may still hold the key because they couldn't be read, rewritten or deleted; they are retried on the next run. Pass `atBoot: true` only before `startAutoSave` has run.
- **Boot** (from Story B): `src/lib/boot.ts` holds `bootMain(deps?)` (sync → `hydrateFromDisk` → `moveAnthropicKeyToVault` → `startAutoSave` → project-setup steps → periodic sync) and `bootDetached()` (auto-save only; never the move). `main.tsx` calls one (and awaits it), then loads the settings store, paints the theme and renders; `src/__tests__/main.test.tsx` pins that. Settings → AI API shows `SavedCopyNotice` (in `AnthropicKeyField.tsx`) whatever the Orchestrator provider. `boot.ts` may statically import only `@tauri-apps/api/core`, `./persistence`, `./sync` and `./anthropicKey`.
- **Known races, accepted and not coded** (from the Story B review):
  - A late pre-launch sync import can put K back on disk until the next launch. `sync.rs` `import_state` reads the local settings file, then writes the imported value with `restore_secrets`, which copies the field from that earlier read. If the move strips `kv/` between the read and the write (the bounded startup wait and its deadline make this a narrow window), K is back in `kv/`; the next launch moves or strips it again.
  - An ErrorBoundary reload of a detached window while it is mid-write can let the next main-window boot scrub delete that window's in-flight `.better-terminal-settings.json.*.tmp`. Its `atomic_write` rename then fails, and auto-save's retry (5 s) writes the value again.
