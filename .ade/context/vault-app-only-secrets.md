# Vault: app-only secrets

Status: approved with `_bmad-output/plan-anthropic-key-in-vault.md` (ADR 0013, accepted 2026-10-30). It becomes current as Stories A and B are Done.

- **App-only names** are listed as literals in `APP_ONLY` in `src-tauri/src/vault.rs`. Today the list is `ADE_ORCHESTRATOR_ANTHROPIC_KEY`, also exported to Rust as `vault::ORCHESTRATOR_ANTHROPIC_KEY`. `vault::in_terminals(name)` is the one test of the list. Each name must pass `valid_name` and must not start with `ANTHROPIC_` or `CLAUDE_`.
- **They are never in a terminal's environment.** `terminal_env` filters the map it returns, on both the cached path and the fresh-read path. The cache itself keeps every name, so its complete-read check still holds.
- **`vault_list`** returns `{ name, note, updatedAt, inTerminals }`. `inTerminals` is computed, not stored. `vault-index.json` is unchanged. TypeScript keeps no list of its own: the Secrets tab (`IntegrationsPanel.tsx`) marks `inTerminals: false` rows "Not in terminals", and picks the save notice from the `vault_list` entry it reads back after `vault_set` (a neutral "saved" notice, and no error, when that read-back fails).
- **`vault_get`** rejects with exactly `"not found"` when there is no entry. Other errors keep `keychain_error`'s text.
- **Readers of `ADE_ORCHESTRATOR_ANTHROPIC_KEY`** (from Story B): the Orchestrator's Anthropic provider (`src/lib/anthropic.ts`) and the one-time move (`src/lib/anthropicKey.ts`). Any `vault_get` allowlist must include it, alongside `DEEPSEEK_API_KEY`. `src/lib/__tests__/vaultGetCallers.test.ts` lists every caller. The Orchestrator has no fallback: not to an `ANTHROPIC_API_KEY` entry, not to the old setting. `"not found"` or `""` gives "No Anthropic API key set. Go to Settings → AI API to add one."; any other rejection is shown as the vault's own message.
- **`src/lib/anthropicKey.ts`** (from Story B) exports `ANTHROPIC_VAULT_NAME` (equal to the Rust literal), `LEGACY_FIELD`, `ANTHROPIC_KEY_NOTE` ("Orchestrator: Anthropic API key. Not exported to terminals."), `moveAnthropicKeyToVault(): Promise<"moved" | "stripped" | "nothing" | "failed">` (never throws), `lastMoveError()`, `hasSavedCopy()` (localStorage holds a non-empty string field), `carryLegacyField(json)` and `removeSavedCopy()` (rejects with the error when the disk write fails). Its only static import is `@tauri-apps/api/core`; `removeSavedCopy` loads `./persistence` dynamically for `flushNow`.
- **The old setting field `anthropicApiKey`** (from Story B) is named only as `LEGACY_FIELD` in `src/lib/anthropicKey.ts`. The settings store never holds it (`migrate()` drops it); `persistSettings` passes its JSON through `carryLegacyField`, which copies the field from the current localStorage value only while it is there. It is also in `SECRET_FIELDS` in `src-tauri/src/sync.rs`, which strips it, and `state_scrub_secrets` uses that list (through `sync::strip_secrets`, now `pub(crate)`).
- **`state_scrub_secrets({ atBoot })`** (from Story B, `state::scrub_secrets(state_dir, at_boot) -> usize`): strips `SECRET_FIELDS` from `better-terminal-settings.json` and deletes `.better-terminal-settings.json.*.tmp` in every `snapshots/*/`, `.kv-old-*` and `.kv-restore-*` directory (stripped, never deleted), and in `kv/` only when `atBoot` is true. Writes only changed files, with `atomic_write`; returns how many files it wrote or deleted. Pass `atBoot: true` only before `startAutoSave` has run.
- **Boot** (from Story B): `src/lib/boot.ts` holds `bootMain(deps?)` (sync → `hydrateFromDisk` → `moveAnthropicKeyToVault` → `startAutoSave` → project-setup steps → periodic sync) and `bootDetached()` (auto-save only; never the move). `main.tsx` calls one, then loads the settings store, paints the theme and renders. `boot.ts` may statically import only `@tauri-apps/api/core`, `./persistence`, `./sync` and `./anthropicKey`.
