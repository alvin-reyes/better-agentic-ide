Agent hub

A hub that remembers each client’s work.

One private repo per client holds its context, state and history. The client’s code stays in its own repos.

Thirteen personas

Focus terminals

bin/work <folder> opens that checkout with its named agent, hooks and model (--model, --agent-model).

State, memory, journal

STATE.md, memory/ and a shared journal; hooks show each terminal what the others changed.

One brain for every agent

A local SQLite brain (FTS5 plus Ollama vectors) that every agent searches before it asks; nothing leaves the Mac.

Auto sync, scanned first

bin/sync --auto pushes every 30 minutes and at session end, gitleaks-scanned, never forced.

Monitors and briefing

Read-only monitors every 30 minutes and a weekday morning briefing on Haiku.

Access and secrets

bin/remote for SSH, bin/secret for the Keychain, bin/doctor for what this Mac can reach.

02

A methodology that decides Done

An agent saying it is finished is not evidence. Every project names who checks the work.

ADE sets the rules; BMAD supplies the workflows.

The framework

BMAD in every project, wired into the roles

The pinned BMAD-METHOD v6 goes into every project: 33 skills in .claude/skills/, config in _bmad/, tickets in _bmad-output/. ADE keeps its own QA gate in .ade/gates/, and nothing you have is overwritten.

BMAD v4 is still a choice. Switching either way is one dialog that lists every path first, archives the old version in .ade/archive/ and puts everything back if a step fails.

Done is decided by a command

A story is Done when the agreed verification command passes on its commit, output shown.

No agent certifies its own work

The Developer writes the failing test first; QA judges and may not edit code or tests.

An adversarial reviewer that cannot patch

A read-only allowlist, Read, Grep, Glob, Bash: it judges, it never patches.

What they learn stays in your repo

A knowledge store per role and a shared context store, committed with the project.

Execution

Where each one acts

The agent that builds a story never signs it off.

  1. Plan

    PRD, architecture with the one verification command, UX spec and ops plan.

  2. Approve

    The adversarial reviewer attacks each artifact; then you approve.

  3. Shard

    The scrum master splits it into small, testable stories.

  4. Build

    Developers take one story each, test first, in parallel.

  5. Verify

    QA or you run the command. It passes, or it is not Done.

FAQ

Common questions

Is it really free?

Yes. Download ADE; nothing is locked.

How does licensing work?

There is nothing to license. ADE is MIT licensed: no licence keys, accounts or seats.

Which agents does it support?

Any CLI agent; ADE goes deepest with Claude Code. Codex and Ollama run beside it but show no cost, because they publish none.

How many agents can run at once?

As many as your machine and rate limits allow. We test ten.

Does it store my keys?

API keys stay in your OS keychain, never synced. ADE never handles private keys.

Which platforms does it run on?

macOS (Apple Silicon, Intel) and Linux (.deb, AppImage), or the install command above. Windows is not built yet: issue #22.
