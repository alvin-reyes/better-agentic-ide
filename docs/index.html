02

Built for serious software engineering work

An agent will tell you it is finished. The question is who checks. ADE sets every project up with a methodology that answers that, and roles that cannot mark their own homework.

The root of all of it

BMAD, in every project and actually used

Not a nod to a methodology. The pinned BMAD-METHOD goes into .bmad-core/ in every project ADE opens: 21 tasks, 13 templates, 6 workflows, 6 checklists and 6 reference sets, plus 21 /BMad:tasks: commands for Claude Code. Nothing is downloaded and nothing you already have is overwritten.

The roles name the ones that do their job, so the Scrum Master shards with create-next-story and QA traces criteria with trace-requirements instead of improvising both. Its two phases, Planning and Dev cycle, are the phases ADE shows you, because they are the ones the work is actually in.

Done is a command, not an opinion

Every project agrees one verification command up front. A story is Done when it passes on that commit, with the output shown. Not when an agent says so.

No agent certifies its own work

The Developer writes the failing test first, then the code. QA judges the result and may not edit code or tests, because a verifier that repairs what it measures can make its own verdict come true.

An adversarial reviewer that cannot patch

It ships with a read-only tool allowlist on purpose: Read, Grep, Glob, Bash. It judges and reports. Widening it to unblock a story is how review stops meaning anything.

Nineteen roles, each with boundaries

Analyst through security engineer, SRE and release manager. Each one states what it owns, what it must not touch, and whose job the rest is, so parallel agents stop contradicting each other.

What they learn stays in your repo

A knowledge store per role, committed with the project. Shared contracts go to the context store where parallel agents read them. An update never overwrites either.

03

How an agent is composed

A prompt that says “you are a senior engineer” is a costume. An agent here is two things joined: a role that fixes what it is accountable for, and a domain that narrows what it is working on. The role is the part that holds.

Role 19

What it is accountable for, the artifacts it owns, and what it must not touch. QA may not edit the code it judges. The adversarial reviewer ships with a read-only tool allowlist.

×
Domain 44

One technical focus: Backend API, Database, CSS, Containers, CI/CD, Solidity. It narrows what the agent knows. It never widens what the agent may do.

=
Agent 47

Named pairings, ready to launch. Developer × Backend API is the API Builder; Developer × Database is the Database Engineer. Same accountability, different ground.

The role’s definition is handed to the provider verbatim, not rebuilt from parsed fields, because it carries sections ADE does not model and a recomposition would silently drop them. The domain is appended as a Focus section underneath. Boundaries survive the pairing by construction, not by convention.

Execution

Where each one acts

Roles are not decoration. Each step of the flow has an owner, and the handoff between them is the point: the agent that builds is never the agent that signs it off.

  1. Plan

    The product manager writes the PRD. The architect writes the architecture and names the one verification command. The designer writes the UX spec, DevOps the ops plan.

  2. Approve

    The adversarial reviewer attacks each artifact first, defaulting to block on any material flaw. Then you approve. A reviewer that waves things through defeats the point.

  3. Shard

    The scrum master splits the plan into small, independently testable stories, so several agents can work without colliding.

  4. Build

    Developer agents take one story each, test first. They run in parallel because each role states what it owns, so two agents do not quietly edit the same artifact.

  5. Verify

    QA or you run the verification command on that commit, with the output shown. A story is Done when it passes. Not when an agent says so.

FAQ

Questions, answered

Is it really free?

Yes. Download ADE; nothing is locked.

How does licensing work?

It does not. ADE is MIT licensed: no keys, no accounts, no seats to count. Use it at work, fork it, ship your own build.

Which agents does it support?

Any CLI agent runs here, but ADE is built around Claude Code and goes deepest with it: sub-agents in .claude/agents/, a CLAUDE.md constitution, sub-agent lanes on the fleet timeline, and real spend read from its transcripts. Codex, Gemini and Ollama run side by side and show no cost, because they publish none.

How many agents can run at once?

As many as your machine and your provider's rate limits allow. Ten is what we test.

Does it store my keys?

API keys stay in your OS keychain, never synced. ADE never handles private keys.

Which platforms does it run on?

macOS (Apple Silicon and Intel) and Linux (.deb or AppImage). Or install from the terminal with curl -fsSL https://ade.ardata.tech/install.sh | bash, which picks the right build for your machine. Windows support is coming soon.
